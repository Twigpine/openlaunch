# Standalone security hardening

The application security fixes previously included in bridge PR #135 are separated onto `codex/security-hardening`, based on main `70e4fa2ac1dc18832982f4d7e33ae76b80c077d8`. Their source is the reviewed combined head `be857d86006ce7ded2e26fe9903a7d16f27c90fd`.

## Scope

- Prevent upstream RPC details from leaking through API errors.
- Bound request bodies, use the shared client-IP policy, and preserve upload, post, report, profile and edit quotas across rejected requests and transaction rollback.
- Reject malformed indexer text and recover canonical chain history, derived balances, fees, points and pair-payment accounting after a reorg.
- Preserve pending launch transactions and expose recovery states without prompting a duplicate submission.
- Include the associated regression suites and contract assumption/invariant tests. Deployed contract sources, dependency pins and CI workflows are unchanged.

Bridge network support, quote/history endpoints, UI and Circle/Relay recovery remain in [PR #135](https://github.com/Twigpine/openlaunch/pull/135). In particular, uncertain Circle burns and known-hash recovery checks stay with the bridge implementation. Neither PR depends on the other to compile or run.

Two shared files require a hunk-level split: the RPC route keeps main's network selection while gaining bounded input and shared IP handling here; TradePanel gains canonical sync feedback here while the bridge PR retains its bridge-to-buy controls. All other security implementation files retain the reviewed source content, including subsequent main changes already incorporated into that source.

## Rollout

The standalone security PR owns the schema and canonical-history rollout. Follow [Canonical index recovery](2026-11-12-reorg-recovery.md): stop old indexer writers before deploying, retain a database backup, and allow the one-time resumable historical rebuild to complete. Market data can temporarily show recovery states. Splitting the PR does not remove these operational requirements or establish a vulnerability-free guarantee.
